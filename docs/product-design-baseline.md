# Sway / 言和产品设计基线与低保真原型

## 1. 设计目标

Sway 的第一版要解决一个明确问题：用户在聊天时不知道怎么把话说得自然、得体、有情绪价值。

产品不是替用户聊天，也不是自动读取聊天记录的工具。它只处理用户主动输入、复制、粘贴或导入的上下文，生成可选择的候选表达，最终发送动作始终由用户完成。

## 2. MVP 冻结范围

- 平台：iOS only。
- 客户端：主 App + iOS Keyboard Extension 同期交付。
- 后端：生成 API + Provider 配置 + 历史/样本 + 用量限制 + 后台管理。
- 模式：改写草稿、根据对方消息回复、破冰、安慰、道歉、拒绝。
- 身份：游客模式优先，预留登录扩展点。
- 模型：用户在 App 内自配 LLM Provider，后端代理调用。
- 语言：中文和英文。
- 隐私：历史和样本可保存 1 个月，必须提供清理入口。
- 发布：TestFlight / 自用，不按正式上架节奏推进。

## 4. 主 App 低保真

### 4.1 首次启动

```text
┌────────────────────────────┐
│ 言和 Sway                  │
│ 把话说得更好听，也更像你   │
│                            │
│ [开始使用]                 │
│ [了解隐私说明]             │
└────────────────────────────┘
```

首屏只做价值说明，不放复杂功能介绍。隐私说明必须明确：不会自动读取微信完整聊天，只处理用户主动提供的内容。

### 4.2 首页 / 生成页

```text
┌────────────────────────────┐
│ 生成回复            设置    │
├────────────────────────────┤
│ 模式：回复 / 改写 / 破冰    │
│ 语言：中文 / English       │
│                            │
│ 对方消息                   │
│ ┌────────────────────────┐ │
│ │ 粘贴对方消息或 OCR 导入 │ │
│ └────────────────────────┘ │
│                            │
│ 我的草稿                   │
│ ┌────────────────────────┐ │
│ │ 可选，输入你原本想说的话 │ │
│ └────────────────────────┘ │
│                            │
│ 语气：温柔 幽默 真诚 克制  │
│ 长度：短 / 中              │
│                            │
│ [生成 3 条候选]            │
└────────────────────────────┘
```

设计重点：

- 用户先选模式，再输入上下文。
- 对方消息和我的草稿分开，避免 prompt 混乱。
- 语气用按钮，不让用户写复杂提示词。

### 4.3 候选结果

```text
┌────────────────────────────┐
│ 3 条候选                   │
├────────────────────────────┤
│ ① 我懂你的意思，其实我也... │
│ [复制] [收藏]              │
│                            │
│ ② 哈哈你这么说我有点心动...│
│ [复制] [收藏]              │
│                            │
│ ③ 我想认真回应你一下...    │
│ [复制] [收藏]              │
│                            │
│ [换一批] [调整语气]        │
└────────────────────────────┘
```

候选原则：

- 固定 3 条，避免选择负担。
- 每条不超过 80 字，适合聊天。
- 只复制或插入，不自动发送。

### 4.4 Provider 配置页

```text
┌────────────────────────────┐
│ 模型配置                   │
├────────────────────────────┤
│ Provider  OpenAI / Qwen    │
│ Base URL  ***************  │
│ Model     qwen-plus        │
│ API Key   ***************  │
│                            │
│ [测试连接]                 │
│ [保存配置]                 │
│ [清除配置]                 │
└────────────────────────────┘
```

约束：

- API Key 不明文回显。
- Keyboard Extension 只读配置状态，不直接展示密钥。
- 未配置时，生成入口提示先配置模型。

### 4.5 历史与隐私

```text
┌────────────────────────────┐
│ 历史记录                   │
├────────────────────────────┤
│ 今天                       │
│ - 回复：你这样说我很开心...│
│ - 道歉：这件事是我没处理好...│
│                            │
│ [清理全部历史]             │
└────────────────────────────┘
```

隐私设置：

- 展示历史保留 1 个月。
- 提供“立即清理历史和样本”。
- 说明内容仅来自用户主动输入/导入。

## 5. Keyboard Extension 低保真

键盘区域必须轻。复杂设置、长文本编辑、历史管理都放主 App。

```text
┌────────────────────────────┐
│ Sway  回复 改写 破冰 道歉  │
├────────────────────────────┤
│ 语气：温柔  幽默  克制     │
│ [粘贴对方消息] [改写草稿]  │
│                            │
│ ① 好呀，我其实也挺想...    │
│ ② 你这么说我会认真想...    │
│ ③ 哈哈，那我先记住了...    │
│                            │
│ 未开启完全访问？去 App 生成 │
└────────────────────────────┘
```

键盘内只保留：

- 模式切换。
- 语气选择。
- 粘贴对方消息。
- 改写当前草稿。
- 生成按钮。
- 3 条候选。
- 插入候选。
- 错误和无权限兜底。

不放：

- Provider 编辑。
- 历史列表。
- 隐私长文。
- 登录/会员。
- 后台入口。

## 6. 六个模式定义

| 模式 | 输入重点 | 输出目标 |
| --- | --- | --- |
| 改写草稿 | 我的草稿 | 更自然、更得体、更像真人 |
| 根据对方消息回复 | 对方消息，可选我的草稿 | 给 3 条可直接发送的回复 |
| 破冰 | 对方资料/一句开场目标 | 不尴尬、轻松开启话题 |
| 安慰 | 对方负面情绪 | 共情、安抚、不说教 |
| 道歉 | 事件、我的态度 | 承担责任、修复关系 |
| 拒绝 | 对方请求、拒绝原因 | 有边界、不伤人 |

每个模式都支持中文/英文输出。

## 7. 错误态与兜底

| 错误 | 用户文案 | 行动 |
| --- | --- | --- |
| 未配置模型 | 还没有配置 AI 模型 | 去 App 配置 |
| 无完全访问 | 当前键盘不能联网生成 | 去 App 内生成 |
| 输入过长 | 内容有点长，先删短一点 | 返回编辑 |
| 模型超时 | 这次生成超时了 | 重试 / 使用本地模板 |
| 安全拒绝 | 这段内容不适合生成 | 给健康表达建议 |
| 服务不可用 | 服务暂时不可用 | 稍后重试 |

## 9. 品牌方向

品牌名：言和 / Sway。

设计气质：

- 温柔高级。
- 年轻可爱。
- 不油腻、不像恋爱话术库。
- 更像“表达修辞工具”，不是“撩人作弊器”。

主色建议：

- Warm Coral：`#FF7A7A`，表达温柔和亲近。
- Soft Cream：`#FFF7F0`，用于背景。
- Ink Brown：`#3B2F2F`，用于正文。
- Mint Accent：`#75D6C2`，用于轻提示和成功态。

Logo 方向：

- “言”字气泡 + 柔和波纹。
- 也可以用字母 `S` 做成轻微对话气泡形。
- 避免爱心过多，避免过度恋爱化。

## 10. M1 验收

M1 产品与工程要达成：

- 用户能在主 App 配置 Provider 并测试连通。
- 用户能在主 App 里选择模式、输入上下文，得到 3 条候选。
- 六个模式的入口已经确定，至少 M1 先跑通改写和回复。
- 错误码能映射成用户可理解文案。
- Keyboard Extension target 已存在并可运行，哪怕功能尚未完整。
- 后台管理范围和页面结构已冻结。
